# Machine notes: agent-lxc

Applies only on the agent LXC (profile `agent-lxc`): Proxmox LXC 2026, hostname `agent`, `172.16.2.26`, Debian 13, user `derek` (uid/gid 1000), bash, headless. Where a shared rule or skill says "see the machine notes", these facts win.

- **Layout:** agents and their config live on the `/opt` mount. `~/.agents` is a symlink to `/opt/config/.agents`, so the kit is at `/opt/config/.agents/agent-kit`. Claude Code runs with `CLAUDE_CONFIG_DIR=/opt/config/claude` and Codex with `CODEX_HOME=/opt/config/codex` (`~/.claude` and `~/.codex` are symlinks to them).
- **Install and update of the kit:** `/opt/scripts/startup.d/agent-kit-startup.sh` clones the repo and runs `install.sh --profile agent-lxc` on every container start. `/opt/updater.sh update` also pulls. Documentation: `services/2026-agent/README.md` in the proxmox-services repo.
- **Workspace path:** `/workspace` (same dataset as on LXCs 2028, 2029, 2011). The Mac's `/Volumes/private/workspace/...` paths do not exist here.
- **No docker, no podman, no uv, no pip.** For anything that needs Docker or Podman, use the `docker-hosts` skill (LXC 2028 / 2029). Published ports are on the docker LXC's IP, and `portbridge` (running on those LXCs) makes their loopback-only ports reachable there; the reachable address is in `/workspace/.portbridge/<host>.json`, readable from here without ssh.
- **Installing tools:** no Homebrew. Anything not installed by apt goes in `/opt/tools/<name>`, its config in `/opt/config/<name>`, its binary symlinked into `/opt/config/bin` (already on `PATH`), and its caches in `/mnt/cache` (this LXC only) or `/mnt/sharedCache` (shared across LXCs). Ask the user before installing anything, and propose where it goes first.
- **Worktrunk:** installed and kept up to date by `/opt/scripts/startup.d/wt-startup.sh` (binary `/opt/tools/worktrunk/bin/wt`), which also installs the agent plugins (Claude, Codex, opencode, Pi) so agents create worktrees through `wt`. Do not suggest `brew`. If `wt` is missing, the fix is to run that script.
- **markitdown:** not installed, and nothing here provides `uv` or `pip`. It would have to go under `/opt/tools/markitdown` per the convention above. Ask first and propose the install plan; do not improvise one.
- **How rules reach each agent:** Claude Code reads `~/.claude/rules/` (symlink to `~/.agents/rules`). Codex, Gemini/Antigravity, opencode, and Pi get a managed block written by `install.sh` into their `AGENTS.md` / `GEMINI.md` (their config dirs are redirected under `/opt/config`; Pi: `$PI_CODING_AGENT_DIR`). Orca launches those agents and has no instructions file of its own.
- **Skills:** third-party skills are installed by `/opt/scripts/startup.d/skills-startup.sh` into `~/.agents/skills`. Kit skills are symlinked into the same place.
- **GitHub:** `gh` is logged in as `hereisderek` and an SSH key for GitHub is in place, so `git@github.com:` URLs work. The kit itself is public and is pulled over https.
